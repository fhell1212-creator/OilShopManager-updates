# نظام إدارة محل الزيوت والصيانة

تطبيق سطح مكتب عربي (RTL) يعمل محلياً على Windows باستخدام Python 3.11+ وTkinter وSQLite، بدون إنترنت وبدون أي خدمة سحابية. البيانات التشغيلية محفوظة في `%LOCALAPPDATA%/OilShopManager/shop.sqlite3` والنسخ الاحتياطية ملفات SQLite قابلة للنقل.

## الواجهة

تصميم «الغرافيت والكهرمان»: شريط جانبي غرافيتي عائم قابل للطي، بطاقات Soft UI فاتحة بظلال ناعمة، وإجراء أساسي كهرماني بلون الزيت. مصدر الألوان التنفيذي `ui.py`، وتوثيقها في `DESIGN.md` و`design/colors.json`.

الشاشة الرئيسية تعرض إجراء «عملية جديدة»، مؤشرات اليوم، المواعيد القادمة وآخر الفواتير. حُذفت الاختصارات المتكررة وبطاقات عرض الطرازات. بدء العملية أصبح اختيار السيارة ثم متابعة تبديل الزيت.

حُذف الكتالوج وميزة ملصقات السيارات بالكامل: الصفحات، الأزرار في السيارات وملف العميل، التوليد والحفظ والإرسال الخاص بالملصقات. بيانات السيارات والفواتير السابقة تبقى محفوظة، نوع السيارة أصبح نصاً اختيارياً في ملف العميل ويمكن تدوينه لاحقاً. رمز QR الموجود على الفاتورة مستقل ويستمر بالعمل.

## أدوات المعاينة

- `python tools/screenshot_app.py` لمعاينة الرئيسية على قاعدة منفصلة.
- `python tools/screenshot_modals.py` لمعاينة النوافذ المنبثقة.
- `python tools/smoke_test.py` لفتح شاشات التطبيق.
- `python tools/preview_ui.py` لمعاينة حالات الأزرار والأيقونات.

## المشتريات والمبيعات اليدوية — 2026-11-02

- «المشتريات» لإدخال المواد، و«بيع جديد» من المبيعات لإخراجها. المورد والعميل والصنف ورقم الفاتورة والتاريخ وطريقة الدفع حقول قابلة للكتابة، والقوائم تقترح السجلات الموجودة.
- الصنف الجديد والمورد الجديد يُنشآن عند حفظ الشراء فقط. تعديل أسطر المسودة وحذفها أو إغلاق النافذة لا يغيّر المخزون أو يسجل دفعات.
- اكتب الكمية وسعر الوحدة والمبلغ المدفوع أو المستلم فعلياً. لا يُملأ السعر أو مبلغ الدفع تلقائياً؛ زر «دفع كامل الإجمالي» يعبئه عند طلبك فقط.
- البيع يسحب من المخزون عند تفعيل علامة السحب، مع التحقق من الكمية والوحدة. ارفع العلامة لتسجيل بند حر باسم وسعر يدويين بدون حركة مخزنية. إنشاء فاتورة البيع اليدوية متاح للمدير، وتبقى صلاحيات الأصناف والموردين محفوظة.
- الاتفاقات والمبالغ المتبقية ملاحظات يدوية، ولا تُنشأ ديون تلقائية. حفظ الفاتورة وحركات المخزون والدفع عملية واحدة، وتُلغى كلها إذا فشل أحد البنود.
- البحث في القائمتين يشمل اسم الصنف، وتظهر الأصناف والإجمالي والمدفوع مع بيانات الفاتورة. اختبارات المسارات اليدوية: `python -m unittest discover -s tests -p test_manual_trade.py`؛ المعاينة ببيانات مؤقتة: `python tools/preview_manual_trade.py`.

## سجل العمليات — التعديل والحذف والنسخ التلقائي

شاشة «سجل العمليات» (للمدير فقط) تعرض من نفّذ كل عملية ومتى وعلى أي سجل، وأصبح فيها:

- **بحث وتصفية** بالنص الحر (المستخدم، العملية، التفاصيل) أو بنوع العملية من قائمة مملوءة تلقائياً.
- **تعديل السجل المحدد** — يفتح نافذة لتعديل العملية ونوع السجل ورقمه والتفاصيل. يمكن الضغط المزدوج على السطر أو زر `Delete`.
- **حذف السجل المحدد** — بعد تأكيد يعرض تفاصيل السجل قبل الحذف.
- **نسخة أمان قبل التعديل** — تُحفظ نسخة كاملة مُتحقَّق منها قبل أي تغيير، باسم `before_audit_change` في مجلد النسخ.
- **تنظيف السجلات القديمة** — حذف كل السجلات الأقدم من عدد أيام تختاره.

**مبدأ أمان السجل:** أي تعديل أو حذف على سجل العمليات **يُسجَّل نفسه** كسجل جديد («تعديل سجل عملية» / «حذف سجل عملية» / «حذف سجلات قديمة») باسم المستخدم المنفّذ وقبله وبعده. فالسجل لا يمكن غسله: يظهر دائماً ما جرى حذفه ومن حذفه.

**النسخ التلقائي** يعمل كما هو: نسخة يومية (أو أسبوعية) تتحدّث عند التشغيل وكل ساعة وعند الإغلاق، وتُعرض آخر مرة نسخ في مؤشر الشاشة وفي «مركز البيانات». أي خطأ في النسخ يُحفظ في `backup_error` ويظهر للمدير.

## مخطط المعمارية

```text
واجهة Tkinter RTL (app.py): قائمة جانبية بمجموعات، بطاقات مؤشرات، نوافذ منبثقة موحّدة
                  │ استدعاءات داخلية
                  ▼
طبقة قواعد العمل والتحقق (database.py)
     ├── مصادقة كلمات المرور PBKDF2
     ├── حساب الفاتورة والذمم ومواعيد الزيت
     ├── سجلات السيارات السابقة للأرشيف فقط
     ├── معاملات SQLite ذرية للمبيعات والمخزون
     └── سجل التدقيق والنسخ الاحتياطي
                  │
                  ▼
رمز الفاتورة (qr_engine.py): ترميز بيانات السيارة ورمز QR
                  │
                  ▼
SQLite محلية: فهارس، علاقات، foreign keys، WAL
```

الواجهة وقواعد البيانات منفصلتان؛ يمكن لاحقاً تبديل طبقة التخزين دون إعادة كتابة الشاشات. أول تشغيل يعرض إعداد المحل وينشئ حساب المدير.

## الشاشات

الرئيسية، عملية جديدة، العملاء، المشتريات، المبيعات والفواتير، المخزون، المصروفات والحسابات، والإدارة. الخدمات والموردون والتقارير والنسخ والإعدادات داخل الإدارة.

## التشغيل من المصدر

```bat
start.bat
```

أو مباشرة: `python app.py` (يتطلب Python 3 مع Tk). للواجهة ورمز QR تُثبَّت تبعيات `requirements.txt`:

```bat
python -m pip install -r requirements.txt
```

بيانات الدخول الافتراضية بعد الإعداد الأول: **admin / admin** — يُنصح بتغييرها من إدارة المستخدمين.

## بناء ملف EXE

```bat
build_exe.bat
```

الناتج `dist/OilShopManager.exe` — نسخة مستقلة تتضمن Python وTkinter ومكتبات الواجهة ورمز QR، لا تحتاج تثبيت Python أو إنترنت. شعار المحل داخل `assets/branding` ومضمّن في الملف. عند نقل العمل لجهاز آخر انسخ النسخة الاحتياطية من `%LOCALAPPDATA%/OilShopManager` واستعدها من صفحة الإعدادات.

## نطاق الإصدار

تسجيل دخول بأدوار مدير وموظف ومحاسب، وعمليات مرتبطة بالعميل مع نوع سيارة اختياري، ومخزون ومشتريات ومصروفات وفواتير وتقارير ونسخ احتياطية. ملاحظات الحساب تُكتب أثناء العملية وتُعدل لاحقاً من الفاتورة أو ملف العميل؛ لا توجد واجهة ديون أو تحصيل آلي. تظل مبالغ الفواتير والمبالغ المستلمة وسجلات الدفع السابقة محفوظة.

## التحقق

`python -m unittest discover -s tests` يفحص الحسابات والمخزون والصلاحيات والنسخ الاحتياطية والفواتير ورمز QR، إضافة إلى تباين الألوان وحالات الأزرار وغياب ميزتي الكتالوج والملصقات. `python tools/smoke_test.py` يفتح الشاشات والنوافذ على قاعدة بيانات منفصلة.

## تحديث الواجهة — 2026-10-28

رئيسية بمؤشرات مالية ومخطط المبيعات، وشاشة لتحليلات المبيعات. أُلغي قسم السيارات ومواعيدها، وأصبحت العمليات مرتبطة بالعميل مباشرة. التنبيهات والإعدادات موزعة على تبويبات. النماذج الطويلة تدعم التمرير، والإجراءات تلتف عند نقص العرض، والجداول تدعم الفرز بالضغط على العنوان وحالات العرض الفارغة.

الاختصارات: `Ctrl+F` للبحث الشامل، `Ctrl+N` لعملية جديدة، و`F5` لتحديث الصفحة. تقليل الحركة متاح من الإعدادات ويُحترم أيضاً إعداد ويندوز. تحديث ملف EXE الجاهز موجود في `dist/updated/OilShopManager.exe`.

للمعاينة ببيانات تجريبية معزولة: `python tools/screenshot_app.py "الرئيسية" --demo --size 1180x720 --out tools/shots/preview.png`. يتاح `--bottom` لتصوير أسفل نموذج طويل و`--tab 1` لاختيار تبويب الإعدادات الثاني.

## مركز البيانات والنسخ اليومية

من «مركز البيانات» يستطيع المدير إنشاء نسخة كاملة، مشاهدة الأرشيف وتواريخه وأحجامه، فحص سلامة نسخة، تصديرها إلى فلاش واستعادتها. تشمل النسخة قاعدة بيانات المحل كاملة: العملاء والسيارات والفواتير والمبيعات والمشتريات والمخزون والإعدادات والمستخدمين والسجلات. الصور الخارجية المضافة بمسار مخصص ليست جزءاً من قاعدة البيانات ويجب حفظها بشكل منفصل.

عند أول تشغيل لهذا الإصدار يُفعّل النسخ اليومي. تُحدّث نسخة اليوم عند التشغيل وكل ساعة وعند الإغلاق، وتبقى نسخ الأيام السابقة دون حذف تلقائي. يظهر آخر خطأ نسخ في مركز البيانات. النسخ تُفحص قبل اعتمادها، وتُكتب إلى ملف مؤقت ثم تُستبدل النسخة المكتملة. الاستعادة تفحص توافق الجداول والعلاقات، وتحفظ نسخة أمان من البيانات الحالية، ثم تغلق التطبيق لتحميل البيانات المستعادة عند إعادة التشغيل.

زر «جدولة ويندوز يومياً 20:00» يسجل مهمة محلية باسم OilShopManager-DailyBackup تشغّل نفس EXE مع --daily-backup. تعمل المهمة عند تشغيل ويندوز وتسجيل دخول المستخدم حتى لو كان التطبيق مغلقاً. أبقِ EXE في مكان ثابت؛ عند نقله فعّل الجدولة مجدداً. لا يمكن إنشاء نسخة أثناء إطفاء اللابتوب؛ سيُحدّث الأرشيف عند تشغيل التطبيق لاحقاً. تعطيل النسخ من الإعدادات يجعل المهمة تتوقف عن إنشاء نسخ أيضاً.

النسخ المحلية في %LOCALAPPDATA%\OilShopManager\backups. يُنصح بتصدير نسخة دورياً إلى قرص خارجي لحماية البيانات عند تلف القرص الأساسي. لا تُعد النسخة المحلية مزامنة سحابية.

## العمل بالعميل فقط

حُذفت شاشة السيارات وقوائم اختيارها وإضافتها وتعديلها، وشاشة المواعيد وتنبيهاتها وتقارير السيارات. «عملية جديدة» تختار العميل مباشرة، مع حقل «نوع السيارة» الاختياري كنص حر. يمكن تسجيل العميل دون هذا الحقل ثم تعديله لاحقاً، وتظهر العمليات في ملف العميل. لا تُنشأ سجلات سيارات تلقائية.

تُرقّى قاعدة البيانات تلقائياً مع إبقاء العملاء والفواتير والعمليات وسجلات السيارات السابقة. تستمر قراءة النسخ الاحتياطية القديمة وتُرقّى بعد استعادتها وإعادة تشغيل التطبيق. ملف EXE المحدث: `dist/updated/OilShopManager.exe`.

## الواجهة المبسطة والملاحظات — 2026-11-01

القائمة الرئيسية ثمانية أقسام، مع وصول مباشر للمشتريات والمبيعات. الخيارات المتقدمة داخل «الإدارة» أو «المزيد» أو «تفاصيل إضافية». تسجيل العميل يحتاج الاسم والهاتف؛ نوع السيارة اختياري، وبقية البيانات مخفية إلى حين الحاجة. في الحساب تظهر بيانات الخدمة الأساسية والمبلغ المستلم وملاحظات الحساب، مع زر حفظ واضح.

تظهر آخر ملاحظة للعميل عند بدء حساب جديد، ويمكن تعديلها قبل الحفظ أو بعده من الفاتورة وملف العميل. الملاحظات نصوص يدوية ولا تنشئ رصيد دين ولا تسجل دفعة عند تعديلها. المبلغ المستلم يُملأ بإجمالي الحساب حتى تعدله بنفسك، ويظل مستقلاً عن نص الملاحظة. وتوجد ملاحظات قابلة للتعديل لمشتريات الموردين أيضاً.

عند فتح قاعدة بيانات سابقة، تُحفظ نسخة أمان مفحوصة في `backups/before_manual_notes_*.sqlite3` قبل تحويل أرصدة العملاء والموردين إلى نصوص تذكير. تبقى إجماليات الفواتير والمدفوعات الفعلية وسجلات الدفع كما هي. يُلغى رصيد المتابعة الآلي للعملاء، وتُنفذ الترقية مرة واحدة. الملاحظات القديمة والفواتير والمنتجات لا تُحذف. النسخ الأقدم تُقبل وتُرقّى بعد الاستعادة وإعادة التشغيل.

التحقق: `python -X utf8 -m unittest discover -s tests`، ثم `python -X utf8 tools/smoke_test.py`. أمثلة المعاينة المعزولة: `python tools/screenshot_app.py "عملية جديدة" "العملاء" "المبيعات والفواتير" --demo --size 1180x720 --out tools/shots/simple-notes`.
